# ENH-007 — 0.3.0 API Modernization Release Plan

> Status: proposed · Effort: High (2–3 days + downstream PRs) · Impact: type-safe public API, one coordinated downstream migration
> **Maintainer-gated: this is a breaking release. Do not start without explicit approval
> of the scope below.** Publishing goes through CI only (repo policy) and needs explicit
> user confirmation.

## Goal

Ship the four breaking changes the audit deferred (AUDIT.md: ARC-106, ARC-109,
ARC-113, ARC-108) as ONE coordinated 0.3.0 release with deprecation shims where
possible and a migration guide — so downstream (`osm-to-bedrock`, `osm-world`)
migrates once, not four times.

## Scope (from AUDIT.md; re-read those entries for full context)

1. **ARC-106 — `BBox` newtype** replacing `(f64, f64, f64, f64)` in ~15 public
   signatures, `[f64; 4]` in cache meta (serde-compat — see step 4), and the four
   scalar args in `srtm::tiles_for_bbox`/`download_tiles_for_bbox`.
2. **ARC-109 — `OsmData` construction/encapsulation**: builder with named setters;
   the five still-`pub` fields (`relations`, `bounds`, `poi_nodes`, `addr_nodes`,
   `tree_nodes`) become `pub(crate)` with read accessors mirroring 0.2.1's
   `nodes()/ways()/ways_by_id()`; struct docs corrected.
3. **ARC-113 — `OsmRelation::id: i64`** populated by all three parsers; writer uses
   real IDs (fallback `writer_relation_id(idx)` only for synthetic relations);
   round-trip preserves relation identity.
4. **ARC-108 — one progress-callback type**:
   `pub type ProgressFn<'a> = &'a mut dyn FnMut(f32, &str);` everywhere; srtm's
   `(usize, usize, &str)` counts fold into the fraction + message.
5. Carried context (already released as non-breaking, document in the guide):
   SEC-105 key-alphabet contract; any ENH-003 POI expansion if batched here.

## Implementation Steps

1. **Branch**: work on a worktree branch `v0.3-dev` (repo git policy: worktree for
   non-trivial work). Rebase onto latest `main` before merging.
2. **BBox first** (everything else touches signatures that then take `BBox`):
   - Promote the Phase-1 `validate_bbox` helper's module to `pub mod bbox` (or add
     `src/bbox.rs`): `pub struct BBox { pub south: f64, pub west: f64, pub north: f64, pub east: f64 }`
     with `#[derive(Debug, Clone, Copy, PartialEq, Serialize, Deserialize)]`,
     `BBox::new(south, west, north, east) -> anyhow::Result<Self>` (runs validation),
     `impl TryFrom<(f64, f64, f64, f64)> for BBox` (S,W,N,E order — the crate's
     documented order), `fn wsen(&self) -> (f64, f64, f64, f64)` for the Overture CLI
     ordering, and `fn as_swne(&self) -> (f64, f64, f64, f64)`.
   - Migrate signatures crate-wide. Enumerate every site mechanically:
     `grep -rn "f64, f64, f64, f64" src/ tests/ benches/` AND
     `grep -rn "min_lat\|south:" src/` — plus par-mem `get_impact` on each public fn
     if the index is live. Do not trust a single grep (global rule 10): also check
     doc comments, `[f64; 4]` cache-meta sites, and the srtm scalar-arg pair.
   - Keep `impl From<BBox> for (f64, f64, f64, f64)` so downstream migration is
     mostly `BBox::new(a, b, c, d)?` at call boundaries.
3. **Cache metadata compatibility decision** (make it explicit, don't stumble into
   it): `CacheMeta` currently stores `[f64; 4]`. Option A: keep `[f64; 4]` in the
   serialized form (custom serde or a `From` at the boundary) — **old caches stay
   readable; choose this** unless the maintainer wants a cache version bump. Add a
   test deserializing a 0.2-era meta JSON fixture string.
4. **OsmData builder** (ARC-109): implement per AUDIT-REMEDIATION-PLAN.md's ARC-109
   entry; all internal `OsmData::new(...)` call sites (tests included — many) migrate.
   Keep `new` as `#[deprecated]` for 0.3, delete in 0.4, OR remove now — maintainer's
   call; record it in the migration guide either way.
5. **OsmRelation::id** (ARC-113): per the playbook entry; duplicate-relation-ID policy
   copies QA-101's way policy (skip + warn). Extend ENH-002's PBF fixture tests and
   the round-trip integration tests to assert relation IDs survive.
6. **ProgressFn** (ARC-108): per the playbook entry; srtm emits
   `(done as f32 / total as f32, "tile N4x/... (i/total)")` through the shared
   clamped/monotonic `emit_progress` helper. ⚠️ With ENH-001's parallel downloads,
   monotonicity means: report completed-count fractions, not per-tile start events.
7. **Migration guide** `MIGRATION-0.3.md` at repo root: one section per change,
   before/after code snippets, a table mapping every changed public signature old→new.
   Link it from README and CHANGELOG.
8. **Downstream verification**: if `~/Repos/osm-to-bedrock` / `~/Repos/osm-world`
   exist locally, point their `par-osm-rust` dependency at the worktree via a
   `[patch]` or path dep and `cargo check` both; record results in the PR. Do not
   push downstream changes without their own review.
9. **Release mechanics** (after maintainer approval): version 0.3.0 in Cargo.toml;
   CHANGELOG section with every breaking change tagged `**BREAKING**` (house style);
   docs sync pass (README examples, ARCHITECTURE.md, CONTRIBUTING walkthrough);
   `make checkall` + `cargo test --no-default-features` + benches green; tag `v0.3.0`
   at the release commit (per DOC-003's process fix); publish via CI on merge —
   **explicit user confirmation before push/publish**.

## Rollback

Everything happens on the `v0.3-dev` branch — abandoning it costs nothing. After
publish there is no unpublish (crates.io yank only prevents new use); that is why the
downstream compile-check gate (step 8) and the explicit publish confirmation exist.
